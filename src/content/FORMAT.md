## Строка о функции

Каждая функция, которую сайт называет работающей, ссылается на экран реестра v16 и дату проверки на стейдже:

```json
{ "screen": "t014", "verified": "2026-10-10", "title": "Ключевые показатели", "text": "…" }
```

- `screen` — номер записи реестра (`src/data/registry-v16.json`, поле `id`). Статус меняется — строка находится поиском по номеру.
- `verified` — дата, когда функция открыта на стейдже под демо-сетью и снята на снимок (`src/data/verification.json`).
- «Скоро» (`"soon": "ГГГГ-ММ"`) — только для статуса `dev` и только со сроком, подтверждённым Ильясом (Р-4). Без срока строки нет.
- `"earlyAccess": true` у функции — в системе экран помечен «Ранний доступ» (P&L, ДДС): сайт показывает ту же метку (подпись — `platform.json` → `earlyAccess`). Метка блока целиком — `earlyAccess` у блока.
- `tests/content.test.ts` проверяет: у каждой функции номер существует, статус `live` и есть проверка на стейдже, либо `dev` + `soon`.

## Справочник цен (`src/data/prices.json`)

Версия сайта продаёт один тип бизнеса (решение 12.10.2026: РФ — только сеть, ОАЭ — только своё заведение), поэтому у версии
одна модель цены (`model`) и один тип (`segment`); калькулятор берёт тип из контракта A (`window.__vilaxSegment`), но чужой тип
модель версии не меняет (`segmentFor` в `src/lib/pricing-calc.ts`).

- Общие поля: `model`, `segment`, `currency`, `locale`, `taxRate`, `taxLabel`, `showPrices`, `version` (дата цен), `source`,
  `locations` (`min`, `max`, `start` поля «локаций»).
- `model: "v16"` (en, ОАЭ, 1–9): `commercial` — объект страницы продаж v16 байт в байт, расчёт — модуль `VilaxPricing`.
- `model: "blocks"` (ru, сеть РФ, 2–200): `tiers` — тарифы с границами «от/до» (`to: null` — без верхней границы);
  `blocks` — блоки с ценой за локацию в месяц по каждому тарифу (`default` — отмечен в калькуляторе, `earlyAccess` — метка);
  `uk.price` — УК за всю сеть в месяц; `annualDiscount` — скидка за год. Итог = локации × сумма выбранных блоков по тарифу + УК.

В `pricing.json` у пары ru/en одинаковые ключи, но каждая версия рисует только свою модель: группа `blocks` нужна модели blocks
(в en — перевод на будущее), ключи пакетов v16 (`packages`, `calc.staff…`, `calc.lines`) — модели v16. Тест цен проверяет,
что все подстановки строк своей модели и вопросов разрешаются.

## Подстановки

`{base}`, `{guests}`, `{aura}`, `{annualDiscount}`, `{taxRate}`, `{ukPrice}`, `{locationsMin}`, `{locationsMax}`, `{date}` и т. п. в строках цен и вопросов подставляются из `src/data/prices.json` при сборке (`versionVars` и `fill` в `src/lib/pricing-text.ts`; набор зависит от модели версии) — цифры цен в словарях не пишем. `{tier}` (подпись тарифа «2–10») подставляет сам калькулятор.

## Вычитка English (SITE-5, Р-7)

Сомнительные фразы English не помечаются в самих словарях (у пар ru/en одинаковые ключи), а перечисляются в `src/data/needs-review-en.json`: файл, путь к строке, текст как есть, что смущает. Тест сверяет, что пометка указывает на живую строку; поправили фразу — обновите или уберите запись.
